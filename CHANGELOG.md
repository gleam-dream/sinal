# Changelog

## Unreleased — initial release

### Release API redesign

These changes break the pre-release API. [docs/migration-wave-2.md](docs/migration-wave-2.md) lists every removed or changed item with its replacement.

- **Breaking:** event names and field keys are `String`. Sinal checks each segment and key against `[a-z][a-z0-9_]{0,62}` before it creates the atom, so a value built from input fails at definition instead of growing the atom table. Names must still come from source code.
- **Breaking:** definitions are total. `sinal.event(name, measurements, metadata)`, `span.define(name, start_metadata:, stop_measurements:, stop_metadata:)`, `fields.optional`, `fields.enum`, the record builder and `forwarder.new` return the value; a definition bug (invalid name or key, empty name, duplicate key, `optional` over other than one key, reserved span key, empty `with_id`, an event listed twice) panics with a message naming it. `EventError`, `IdentityError`, `PrefixError`, `SpanDefinitionError`, `ConfigError` and `InvalidOptionalInner` are removed.
- **Breaking:** encoding cannot fail. `fields.field(key, encode, decoder)` takes a `fn(a) -> Dynamic` and a `gleam/dynamic/decode` decoder. `FieldError` is `NotAMap | MissingField(key) | InvalidField(key, errors)`. `FieldEncodeError`, `FieldDecodeError`, `EmitError`, `ForwardEncodingFailed`, `SpanOutcome`, `CompletionEncodeError`, `run_span_result` and the panicking `run_span` are removed; `span.run` replaces both runners.
- **Breaking:** a `use`-based record builder replaces `fields.pair` and `fields.imap`: each `use x <- fields.include(field, get: getter)` adds one field and binds its value by name, and `fields.success(Ctor(..))` ends the record. Fields may be listed in any order, two fields of one type cannot swap, and getters need no type annotation; this is the shape of `json/blueprint/codec`'s `field` and `success`. It also replaces the first wave 2 builder (`fields.record`, `fields.parameter`, `fields.and`, `fields.build` and the `Record` type, removed) with the same wire output; see [Follow-up: record builder](docs/migration-wave-2.md#follow-up-record-builder). A record fixes its keys and encoder where it is defined, by running its block with placeholder values, so emitting costs what it did; decoding runs the block again with the decoded values. Add `fields.float` (which also reads an integer), `fields.enum`, `fields.keys` (replacing `declared_keys` and `declared_native_keys`) and `fields.describe_error`.
- **Breaking:** one emission path for libraries. `sinal.emit` returns `Nil` and follows forwarder routes; `forwarder.emit_routed` is removed. `forwarder.emit` stays the path for a package that owns its forwarder and returns the closed `Refusal`. Drop reports and spans ignore routes.
- **Breaking:** handler ids are automatic. `observe(event, run)` returns the `Attachment`. `HandlerId`, `handler_id`, `attach_many`, `with_attachments`, `handler_subscription`, `ScopedCompletion` and `ScopeCleanupFailure` are removed; every registration is a `Subscription` built with `subscription`, `handler(events, run, on_failure)` and `with_id`, and `attach(subscription)` installs one. Handlers attach as the exported `sinal_ffi:handle/4`, so telemetry no longer logs a local-function warning per attachment.
- **Breaking:** errors keep only what can happen. `AttachError` is `AlreadyExists(id)`; `detach` returns `Result(Nil, Nil)`; a scope reports `AlreadyDetached` or `DetachCrashed(description)` in `CleanupFailure`. Add `describe_attach_error`, `describe_handler_failure`, `describe_cleanup_failure`, `describe_scope_error` and `forwarder.describe_refusal`.
- **Breaking:** `forwarder.new(name)` holds 1,024 events (`forwarder.default_capacity`); `forwarder.with_capacity` changes it and a value below 1 fails the start with `InitFailed`. `supervised` returns `ChildSpecification(Forwarder)`. Drop counters live in `persistent_term` under the forwarder's name, so every `Forwarder` of one name shares them. Routes take `List(String)` prefixes.
- **Breaking:** `sinal/span` drops `EventPrefix`, `event_prefix`, `prefix_name`, `prefix_native_name` and the `*_to_dynamic` timing and context helpers; `exception_reason_to_dynamic` and `exception_stacktrace_to_dynamic` become `reason_to_dynamic` and `stacktrace_to_dynamic`. `sinal/exception` is removed.
- **Breaking:** `sinal.event_name` and `sinal.event_native_name` become `sinal.name(event) -> List(String)`.
- Add `sinal.measurement_fields(event)` and `sinal.metadata_fields(event)`, which return an event's codecs, so a test can pin the native maps that `emit` sends with `fields.encode` without attaching a native handler. Fabric needed a test FFI for this.
- Add `fields.check(fields, value) -> Result(Nil, FieldError)`: the error every handler would report for an `enum` value missing from its list, anywhere in a record, without the warning the emit paths log. `fields.enum`'s docs and the README show the test that names every constructor and round-trips it, so an incomplete list fails the application's own tests.
- Internal: `fields.encode_for_emit`, `@internal` in a public module, moves to `sinal/internal/emit` (convention 9). No dependent called it.
- Add `correlation.from_key(key) -> Correlation`, which always succeeds: a key of 1 to 128 bytes is the correlation itself (equal to `from_string`'s), and a longer or empty key becomes its 64-character lowercase hex SHA-256 digest. Two applications silently fell back to `unique()` for ids that did not fit. `from_string` stays the constructor for a value that must be refused rather than hashed.
- Docs: `correlation.required_field()` states that its handler skips and reports an event another emitter sent without a correlation.
- Add `correlation.required_field() -> Fields(Correlation)` for an application event that always carries a correlation, so the metadata holds a plain `Correlation` instead of `Option(Correlation)`. It shares the key `correlation` and the wire encoding of `field()`, so a handler using `field()` reads events emitted with `required_field()` as `Some(..)`, and the reverse. A missing or invalid value fails like any other decode failure: the handler skips that one call, reports `MalformedMetadata` and stays attached. Libraries keep `field()`.
- Add `sinal/correlation`: an opaque `Correlation` of 1 to 128 bytes with `from_string`, `unique` (128 random bits as 32 lowercase hex characters, the shape of a W3C trace id), `to_string`, `field()` (the shared `correlation` metadata key) and `describe_error`. A W3C trace id is a valid correlation. `crypto` joins `extra_applications`.
- Fix: `attach`, `observe` and `with_subscriptions` start the `telemetry` OTP application when it is not running, instead of exiting the caller with `noproc`; `detach` returns `Error(Nil)` when the application is not running.
- Fix: a native map that does not decode no longer detaches the handler. `dispatch` raised after calling `on_failure`, so telemetry removed the handler for good, and every later event of that kind was lost to that subscriber; a `fields.enum` value missing from its list triggered it from ordinary Gleam code. Now the handler reports `MalformedMeasurements` or `MalformedMetadata` to `on_failure`, skips that one invocation and stays attached, in `observe`, `attach`, `with_subscriptions`, forwarder deliveries and span events. `observe` and `subscription` log the failure as a `[sinal]`-domain warning. `HandlerReturned` and crashes still detach. No signature changes.
- Fix: `sinal.emit`, `forwarder.emit` and `span.run` log a `[sinal]`-domain warning in the emitting process, naming the event and the value, when a `fields.enum` value is missing from its list; the event is still emitted with the name. `fields.enum` documents the residual risk: the list cannot be checked against the type.
- Fix: `sinal.emit` returned telemetry's `ok` atom instead of `Nil`.
- Docs: `correlation.from_string` and the migration guide state the 128-byte limit; `correlation.from_key` derives a stable correlation from a longer application id.
- README: lead with the common path and a defaults table; document names as atoms, correlation, and how an application isolates a library with one supervised forwarder and one route.

### Earlier pre-release changes

The entries below describe the pre-release API that the redesign replaced.

- Add BEAM-only typed events and field codecs backed by native `:telemetry` 1.4.2. Handlers receive decoded measurements and metadata synchronously; malformed input or handler failure follows native failure notification and detachment.
- Add explicit attachments, same-shaped multi-event attachments, and scoped subscriptions. Subscriptions acquire sequentially, roll back earlier registrations on failure, and report cleanup failures while retaining successful work results. Catchable exceptions are re-raised with their original class, reason, and stacktrace.
- Add native spans with typed start, stop, and exception descriptors. `run_span_result` retains a completed business result if completion instrumentation cannot be encoded; `run_span` uses a raising policy for encoding failures.
- Add `sinal/forwarder`: a bounded, emitter-side forwarder that hands an event to a dedicated process before any attached handler runs, so a slow or blocked handler stalls the forwarder instead of the producer. `forwarder.emit` never blocks; a send exceeding the configured capacity, or targeting a forwarder that is not currently running, is dropped and reported through `forwarder.dropped_event()` rather than retried. Delivery is best-effort and per-producer FIFO; a handler's `self()` is the forwarder, not the caller; a supervised restart reports and clears whatever was still in flight when the previous incarnation stopped. Additive: `sinal.emit` and `sinal.attach`/`sinal.observe` are unchanged for callers that do not use it.
- Add forwarder routing: `forwarder.route(prefix, forwarder)` and `forwarder.unroute(prefix)` let an application send a library's events through a forwarder by event-name prefix (longest prefix wins, `[]` matches every event), and `forwarder.emit_routed` lets the library emit without choosing. Without a matching route, `emit_routed` is `sinal.emit`; with one, it is `forwarder.emit` to that forwarder: it never blocks, never falls back to inline delivery, drops over capacity (counted in `dropped_event`) or while the forwarder is down (`ForwarderUnavailable`, counted as described below), and keeps each producer's order per route. Routes are node-global and live in `persistent_term`. Additive: `sinal.emit` and `forwarder.emit` never consult routes.
- **Breaking (unreleased API):** `forwarder.Dropped` gains a third field, `unavailable`, and `dropped_event` a third integer measurement of the same name. It counts sends refused with `ForwarderUnavailable`, which were previously silent. The count lives in the `Forwarder` value's atomics and survives restarts; the next incarnation reports it when it starts, and a running incarnation folds a late one (a send that raced its start) into its next drop report. Each report resets what it carries; if no incarnation starts again, the count is never reported. `rejected` and `lost` keep their meaning. Migration: construct or match `Dropped(rejected:, lost:, unavailable:)` (or `Dropped(rejected:, lost:, ..)`); field access and Erlang handlers reading the measurement map are unaffected.
- Add `fields.optional(inner)` so a single-key `Option` field encodes `None` by omitting its key and decodes a missing key, or a raw `nil`/`undefined` marker, as `None`.
- Document every public module. `sinal`, `sinal/fields`, `sinal/span` and `sinal/exception` had no `////` module doc, so `gleam docs` rendered no introduction for them; each now states its responsibility, when to use it, and how it relates to the other modules, with an example for the first three. A test fails if a public module lacks a `////` module doc.
- README: put installation and the common path first, build primitive fields with `fields.int`/`fields.string` instead of `fields.field`, state that the `telemetry` OTP application must be running (without it `attach`, `observe` and `detach` exit with `noproc` and `emit` reaches no handler), replace the `:telemetry.persist/0` promise with how to call it without a sinal wrapper, and add a defaults table.
- Widen the `telemetry` requirement from `== 1.4.2` to `>= 1.4.2 and < 2.0.0`, so an application that mixes Gleam, Elixir and Erlang packages can resolve a later 1.x patch. Sinal uses only telemetry's documented API (`attach_many`, `detach`, `execute`, `span`, failure detachment). The manifest still resolves telemetry 1.4.2, the oracle version CI runs against; `gleam update` moved `gleam_stdlib` to 1.0.5 and `gleeunit` to 1.11.0.

The supported target is Erlang/BEAM. The manifest requires Gleam 1.18 or newer and `telemetry` `>= 1.4.2 and < 2.0.0`; CI exercises telemetry 1.4.2, Gleam 1.18.1 and OTP 28. JavaScript is unsupported. Delivery is synchronous, handler order is unspecified, detach does not wait for callbacks already running, and uncatchable process termination can bypass scoped cleanup. Export and unbounded buffering are outside this library; `sinal/forwarder` is a narrow, bounded, in-process exception to that, not a substitute for a real buffering or export adapter. The package version remains unchanged until a release decision.
