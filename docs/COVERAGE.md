# Sinal design coverage

## Context boundary

- One bounded context owns typed native telemetry. Definitions, native dispatch, registration, scopes, correlation, spans, forwarding and routes share one observation vocabulary and compose recursively inside that context.
- The [design](design/design.typ) describes behavior and ownership. The [glossary](design/CONTEXT.typ) owns canonical meanings. [ADRs](adr/0001-use-the-native-telemetry-registry.md) own material rationale and implementation provenance. [Testing guidance](testing.md) owns repeatable commands.
- `captured` means the named responsibility is specified at its destination. `standard` means an existing conventional artifact needs no package architecture of its own. `out-of-scope` records a deliberate boundary, not a missing inventory row.

## Prior design evidence

- The design layer captures the retained requirements from oversight's `sinal-design.md`, Sinal rows in `API-COVERAGE.md` and `PUBLIC-API.md`, `research/sinal-lifetime-contract.md`, interface-laboratory observation/span/scope notes, Sinal implementation work orders/reviews and release API reviews/decisions. The installation manifest records their section-level destinations before the old corpus is retired.
- Current implementation resolves obsolete signatures and implementation-status claims. Decode failure retention replaces the earlier removal policy; the current custom encoder is total by contract; one route-aware library emission path replaces the intermediate routed API. These changes have explicit ADR rationale rather than historical narration in the architecture.
- Native introspection and `persist/0` remain available to foreign BEAM callers, but Sinal supplies no typed wrapper. Test use of those operations proves interoperability without expanding the public facade.
- Independent semantic and presentation confirmation remains visible in [Pending updates](design/design.typ) until acceptance. An uncertain native attachment outcome and trace-parentage requirements have separate ruling entries; documentation does not silently add recovery or tracing guarantees.
